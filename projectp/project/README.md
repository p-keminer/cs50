# Lights Out

#### Video Demo: https://youtu.be/gmDP3lR0Buo

#### Description:

Lights Out is a small logic game for the terminal. The goal is to solve a puzzle by turning certain fields, or lights, on and off. The game can be played in three different difficulty levels and with different board sizes from 3x3 up to 12x12. I intentionally made the game for the terminal and did not add a GUI, because I wanted to keep the prototype-like terminal style.

## Gameplay

### Basics

The basic idea of the game is that the player can choose a difficulty level and a board size. After that, the program creates a board that was generated by valid moves. This makes sure that the puzzle is solvable in principle. The program also checks that the generated board is not already solved at the beginning.

The board is stored as a 2D matrix. Each field represents one light.
Each light can be either on or off.
An active light is shown as `O`, and an inactive light is shown as `.`.

The goal of the game is to turn off all lights on the board.

### Moves

After the board is generated, the player is asked for a move. A move means one index of the board. The Y-axis uses letters and the X-axis uses numbers. The visible indexes always start at A and 1. Internally, these inputs are parsed and converted into coordinates that Python can use.

Indexes should be entered in the format `Y-axisX-axis`, for example `B2` or `D1`. The parser is quite forgiving, though. It filters out almost everything that does not belong to the input format. For example, ` b-):&(&3` automatically becomes `B3`.

When a field is selected, not only this field is toggled. The horizontal and vertical neighbor fields are toggled as well. Diagonal neighbors are not affected. This is the core rule of Lights Out.

### Other Input Options

The player can also type `help`, `quit`, or `restart`.

With `quit`, the game ends and the program prints a goodbye message.
With `restart`, the current game is stopped and the program asks again for difficulty and board size.
With `help`, the program shows a short help screen with the possible input formats.

### Difficulty and Board Size

The difficulty levels are Easy, Normal, and Hard. Each difficulty level applies a different number of valid moves to the start board. The input is parsed and checked here as well. If the input is invalid, the user is asked again to choose a difficulty level. The parser is also quite forgiving in this part.

The board size is selected by the user. The program asks for a number between 3 and 12 and then creates a quadratic matrix with that size. The input is parsed and validated, so wrong values do not crash the program.

The program can also be stopped at any time with Ctrl + C or Ctrl + D. In that case, the program still exits cleanly and prints a goodbye message.

## Display

As mentioned before, I decided not to use a GUI. The game keeps the prototype style of a terminal application.

At the start of the program, the terminal width is detected. The output is then centered based on that width.

For every question, every move, and every interaction, the terminal is cleared first and then the new output is printed. After every move, the game shows the number of moves so far, the number of lights that are still on, and the current difficulty. It also prints a small hint that the player can type `help`.

## Winning the Game

As soon as all lights are turned off, `has_won(board)` detects the solved state. After that, a short win sequence is played. This sequence toggles all lights several times. Then the game congratulates the player and asks whether the player wants to restart or quit.

At this point, the input is parsed and validated again. Invalid input does not continue the game, but asks the user again for a valid option.

## File Structure

The game logic is in `project.py`.
The tests are in `test_project.py`.
`requirements.txt` is empty because the project does not need any external dependencies outside of Python's standard library.
`README.md` contains the description of the program and the most important design decisions and functions.

The whole game logic is built with modularity and maintainability in mind. This means that the program is split into many small functions, and most of them only have one main job.

The tests are focused on the main logic of the game. During development, this made it easier to test functions one by one before connecting the full game loop.

This was an intentional design decision, because it also makes the game easier to extend later.

Another important design decision was to build the board as a list of lists. Each field only stores a boolean value. This made the board easier to handle and also made the functions easier to test.

The seed was also important during development. It allows reproducible tests and reproducible development games. This made it easier to find and fix systematic problems.

The project only uses Python standard libraries: `re`, `sys`, `random`, `shutil`, `os`, and `time`. Because of that, it does not need any external packages.

The program can be started with:

```text
python project.py
```

The tests can be run with:

```text
pytest test_project.py
```

## Limitations

The game does not include an algorithm that automatically solves the board. It also does not give hints for which moves should be used. There are no cheats or other ways to solve the board. Solving the puzzle is fully up to the player.

## Important Functions

- `main()` controls the start flow and keeps the game running after `restart`.
- `run_terminal_game(size, difficulty, terminal, seed=None)` starts one terminal round.
- `get_difficulty(terminal)` asks for the difficulty and only accepts `EASY`, `NORMAL`, or `HARD`.
- `get_board_size(terminal)` asks for the board size and only accepts numbers from 3 to 12.
- `get_board(size)` creates an empty solved board.
- `get_neighbors(size, row, column)` finds the affected fields of one move.
- `toggle_cell(board, row, column)` toggles one single cell.
- `toggle_cells(board, row, column)` performs a complete Lights Out move.
- `count_lights_on(board)` counts active lights.
- `has_won(board)` checks whether all lights are off.
- `clean_input(text)` removes special characters and validates input.
- `parse_input(text, size)` parses user input and translates it for the game.
- `difficulty_to_moves(difficulty)` translates the difficulty into the number of start moves.
- `generate_puzzle(size, difficulty, seed=None)` creates a not-yet-solved start board from valid moves.
- `format_board(board, on_symbol="O", off_symbol=".")` creates the visible board output.
- `format_stats(move_count, lights_on, difficulty)` creates the status line.
- `center_block(text, width)` centers multi-line text output in the terminal.
- `show_game(board, move_count, difficulty, terminal)` prints the board, status line, and help hint.
- `handle_help(terminal)` shows the help screen in the terminal.
- `handle_quit(terminal)` exits the program cleanly.
- `handle_win(board, move_count, difficulty, terminal)` shows the win sequence and win message.
- `toggle_all_cells(board, move_count, difficulty, terminal)` toggles all cells for the win animation.
- `repeat_win_sequence(board, move_count, difficulty, terminal)` runs the multi-step win animation.
